# Cloudfront e S3

> Você não precisa usar o CloudFront na frente do S3 (mas pode ajudar).

Se tudo o que importa é a escalabilidade, você pode vincular as pessoas diretamente ao URL do S3 em vez de usar o CloudFront. O S3 pode ser dimensionado para qualquer capacidade, então é ótimo se isso for o seu interesse. Além disso, as atualizações estão disponíveis rapidamente no S3, mas você precisa esperar pelo TTL ao usar um CDN para ver a alteração (embora eu acredite que você possa definir um TTL 0s no CloudFront agora, então este ponto provavelmente é discutível).

Se você precisa de velocidade ou está lidando com largura de banda muito alta (10 TB ou mais), convém usar um CDN como o CloudFront na frente do S3. O CloudFront pode [acelerar drasticamente o acesso](http://www.quora.com/What-are-typical-latencies-for-static-content-in-S3-vs-Cloudfront) para usuários em todo o mundo, pois copia seu conteúdo para pontos de presença. Dependendo do seu caso de uso, isso também pode funcionar um pouco mais barato se você lidar com largura de banda muito alta (10 TB +) com números de solicitação mais baixos, pois é cerca de US$ 0,010/GB mais barato para largura de banda do CloudFront do que para largura de banda S3 quando você ultrapassa 10 TB, mas o custo por solicitação é um pouco maior do que se você acessasse os arquivos diretamente do S3. Dependendo do seu padrão de uso, a economia de largura de banda pode compensar o custo extra por solicitação. Como o conteúdo é buscado do S3 com pouca frequência (e a uma taxa muito mais baixa do que o normal), o custo do S3 seria muito menor do que se você estivesse veiculando conteúdo diretamente do S3. A [documentação da AWS no CloudFront](http://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/MigrateS3ToCloudFront.html) explica como você pode usá-lo com o S3.
